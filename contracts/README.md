# Контракты Scrobb

Языконезависимые описания поведения, которое должно совпадать у всех частей Scrobb: бэкенда (Python), веб-приложения и расширения (TypeScript), десктоп-клиента и ядра плеера (Rust). Каждая часть прогоняет эти файлы в своих тестах, поэтому расхождение ловится тестом, а не пользователем.

| Контракт | Что описывает | Кто проверяет |
|---|---|---|
| [`scrobble-rules/v1.json`](scrobble-rules/v1.json) | Правило скроббла: порог прослушивания и подсчёт реального времени звучания ([architecture.md](../docs/architecture.md) §18.7) | Ядро плеера: `player/core/crates/scrobb-rules/tests/vectors.rs`. Позже — бэкенд (повторная проверка, §11.1, шаг 6), расширение и десктоп-клиент |

Планируется:
- **OpenAPI бэкенда** — источник истины для родного API (§18.3) и привязки устройства (§18.4). Из него генерируются TS-клиент веба и DTO в `player/core/crates/scrobb-api`; пока DTO написаны вручную по документу.
- **`match-key/`** — векторы нормализации «артист + трек» (§5.3): по этому ключу плеер и сервер узнают один и тот же трек на разных устройствах (синхронизация рейтингов и плейлистов).

Правила версионирования: файл `vN.json` не меняется после того, как его начал проверять хотя бы один компонент; изменение поведения — новый `vN+1.json`.
